# 新流程：COS 成品导入等待与诊断

本次保持云端新流程、微信优先审核和腾讯云自动审核不变，不启用本机下载/上传或旧生成模式。

## 定位结论与证据边界

- `COS HTTPS 镜像导入失败 HTTP 424` 发生于供应商返回完成结果之后的导入阶段，不等于 AI 生成超时。
- 旧实现普通 GET 收到响应头后立即关闭流，然后立即 HEAD；对象尚未落盘时首次 404 会直接失败。
- 本次核对项目配置的真实 COS 回源：`images/`、Mirror、HTTPS、指定供应商媒体域名均存在。
- 同时间段的一张供应商成品在 COS 中已存在，HEAD/图片信息查询通过，源站 Range 请求返回 206。
- 使用该缓存成品完成了一次独立临时对象的 CI 转 JPEG/落盘检查，HTTP 200，HEAD 返回非空 JPEG，临时对象已删除；没有调用 AI 生成。
- 以上不能单独证明截图每条失败任务的根因。特别是历史 424 未保留原始错误码和请求 ID，本次不把临时重试成功等同于源站权限问题已解决。

## 新导入逻辑

1. 先 HEAD；已经缓存的成品直接复用，不重复触发回源。
2. 缺失时使用 `Range: bytes=0-0` 的 GET。按腾讯云文档，Range 回源会额外触发一次完整对象的异步回填。
3. 不读取成功响应的图片正文；只用 HEAD/图片信息确认实际对象就绪。
4. 404/424/限流/临时服务错误保留在 import 阶段，以调度时间重试，不阻塞工作线程，不重新提交 AI。
5. 回源触发最多 5 次，落盘等待窗口 120 秒，且不超过原任务期限；持续失败才结束任务并走原有退款逻辑。
6. 403 等非临时 COS 对象权限错误直接报错，不循环放行。

## 诊断展示

失败记录保存 `failed_phase`、`failed_stage`、`failed_at`；导入记录保留 `import_diagnostic` 与最近错误。
COS 错误包含操作、对象类别、HTTP 状态、错误码和可取得的请求 ID；错误响应有源站状态时一并提取。
只读取最多 8 KiB 错误正文，不保存原始签名 URL、密钥或整段错误正文。
后台显示当前/失败阶段以及实际存在的耗时；缺失字段不再补成 0 秒。

出现新的 424 时，使用显示的 COS 错误码/请求 ID 与供应商成品地址核对源站响应，区分权限拒绝、重定向、文件尚未可用等原因。
保留 404 来源分类，避免将 uploads/origins/norms/results 的路径问题误判为成品回源尚未完成。
