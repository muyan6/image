# 探针法：反推修图平台的处理链路

在图片里埋入**已知结构的信号**，提交给目标平台，再从返回的图里把信号读回来。
因为输入是已知的，输出的任何偏离都是平台造成的 —— 这就把修图链路变成了可测量对象。

---

## 一、先说清楚能做到什么、做不到什么

### 做不到

**埋信息不能拿到它的模型权重、提示词、或者服务器代码。**
嵌入的信息只是像素，服务端不会把它「读」出来告诉你；返回的就是一张图片。
任何声称能从输出图反推出「它用了什么模型、提示词是什么」的说法都是夸大的。

### 能做到

**精确刻画它的处理链路。** 以下每一条都能从输出图量出来：

| 问题 | 探针 | 判据 |
|---|---|---|
| 它是**判别式超分**还是**扩散模型**？ | p4 | 输出里有没有 8px 周期的 VAE 网格 |
| 有没有**色调曲线 / 滤镜层**？ | p2 | 32 级灰阶的输入-输出映射 |
| 有没有**白平衡**？ | p2 | 灰块的 RGB 增益是否被拉到相等 |
| 缩放了几倍、用**什么重采样核**？ | p1 | 条纹 MTF + 边缘上升宽度与振铃 |
| 降噪**有多强**？ | p8 | 已知 σ=6 的噪声残留比 |
| 有没有**重编码**、元数据留不留？ | p7 | PNG 文本块 / EXIF 是否存活 |
| 是**忠实保留**还是**脑补内容**？ | p5 | 文字的笔画对比度 |
| 细节是**保留**还是**重画**？ | p6 | 多尺度能量分布 |
| 处理是否**确定性**？ | p8×2 | 两次提交的输出是否逐字节相同 |

最后一条信息量最大：**如果两次提交同一张图、输出逐字节相同，那它就不可能是扩散模型**
（扩散采样有随机性，除非固定 seed 且你没传 seed）。这一条几乎零成本就能砍掉一半可能性。

---

## 二、快速使用

```bash
# 1. 生成探针图（8 张，在 input/）
python generate.py

# 2. 把 input/ 里的图逐张提交给目标平台，把返回的图存进 result/
#    文件名里保留 p1..p8，分析器靠它识别类型

# 3. 分析
python analyze.py --dir result --json report.json
```

单张也行：`python analyze.py result/p4_latent.png`

### 提交顺序（按每条小鱼干换到的信息量排序）

1. **p8_flat 提交两次** —— 先定生死。输出相同 → 排除扩散模型；不同 → 生成式，且能看随机性多大。
2. **p2_tone** —— 色调曲线。纯超分的曲线是 45° 直线；有 CLAHE / 阴影提亮的会明显上抬暗部。
3. **p4_latent** —— 8px 网格。这是判扩散模型最硬的一条证据。
4. **p1_resample** —— 缩放倍数与重采样核。
5. **p7_meta** —— 元数据。有时直接暴露工具名（如 `Software` 字段）。
6. **p3 / p5 / p6** —— 补充证据。

**成本提示**：两档价差可能几十倍。先用 `light` 档把 p8 / p2 / p4 跑一遍
（这几张对档位不敏感），确认链路性质后再决定要不要花 `fine` 档的钱。

## 三、各探针的信号设计

### p1_resample —— 重采样指纹

- **条纹扫频**（周期 2/3/4/6/8/12/16/24/32 px）：越细的条纹越先被重采样吃掉。
  哪一根开始变灰，反推缩放倍率的量级；整条 MTF 曲线区分核类型。
- **脉冲栅格**（孤立亮点）：重采样后散成「扩散函数」。
  有振铃（负瓣）→ Lanczos；平滑无振铃 → 双三次 / 双线性；方块 → 最近邻。
- **锐利竖边**：量 10–90% 上升宽度与过冲。

### p2_tone —— 色调与白平衡

- **32 级灰阶梯**：输出的每一级相对输入画出来就是色调曲线。
  线性 = 没动；暗部抬起 = 阴影提亮；斜率 > 1 = 对比度增强。
- **9 个标准色块**：灰块暴露白平衡增益，红/蓝块暴露饱和度处理。

### p3_hifreq —— 高频存活

周期 1 / 2 / 4 px 的棋盘 + 底部平滑渐变对照。
棋盘区高频丢了、平滑区没丢 → 重编码或降噪；两者都丢 → 强重采样。

### p4_latent —— 扩散模型指纹 ⭐

**关键设计**：输入是纯平滑渐变，**刻意不含任何 8px 周期成分**。

扩散模型的 VAE 是 8 倍空间下采样，解码时会留下每 8 像素一周期的网格痕迹。
输入里没有这个频率，输出里出现了 —— 只可能是模型内部带出来的。

**两条证据链并用，缺一不可**：

| 方法 | 能看见 | 会漏掉 |
|---|---|---|
| 1D 行/列均值 FFT | 条纹型网格 | **棋盘型**（沿 x 求和时 +1/-1 互相抵消） |
| 2D FFT，只搜对角 | 棋盘型网格 | **条纹型**（能量在轴对齐频率上） |
| **2D FFT，八方向** | 两类都覆盖 | — |

早期实现只搜对角，`test_grid_detector.py` 的条纹正控直接不过（见 `_grid_test.log`）。
现在每个候选周期同时搜四个轴方向 + 四个对角方向，并各自按本方向的
半径取局部背景中位数，两类峰才可比。

**周期命名约定**（读数容易误判，务必分清）：返回的「周期 p」是沿坐标轴的
重复周期，即 `1/fx` 的分母。

- `p=8` 的**条纹** = 8px 明暗交替，谱峰 `(1/8, 0)`，报 `axis`
- `p=8` 的**棋盘** = 4px 方块交替，谱峰 `(1/8, 1/8)`，报 `diag`
- 8px 方块的棋盘（明暗每 16px 重复）谱峰在 `(1/16, 1/16)`，**报 p=16**

所以棋盘型的读数天然是「方块边长 × 2」。判读时方块边长 = 读数 ÷ 2。

**阈值 8.0 的依据**：恒等基线上各周期比值落在 2~5（实测 p4 最强 2.73），
真实 VAE 网格能到 15 以上 —— 8.0 留了足够余量。
`test_grid_detector.py` 用三组控制验证这条线：负控（平滑渐变、纯随机噪声）
必须不命中，正控（8/16px 棋盘、8/16px 条纹）必须命中。

### p5_text —— 生成式 vs 判别式

图里写大字 + 8px 小字。
判别式方法（ESRGAN 类）会忠实保留笔画；扩散模型倾向于把陌生字形「脑补」成别的形状。
量笔画对比度：大幅下降 = 被重画或糊掉。

### p6_texture —— 细节保留 vs 重画

四个尺度的合成噪声。分析各尺度的能量分布：
- 保真超分：统计特征基本保持
- 生成式：低频能量上升、高频分布改变（模型在重画纹理）

### p7_meta —— 元数据存活

像素是灰色渐变，真正的载荷在 EXIF（7 个字段）和 PNG tEXt（3 个块）里。
只要有一项存活，就说明平台**没有对所有输入做统一重编码** —— 这本身是重要的架构信息。

### p8_flat —— 降噪强度

7 级灰底，每级加**已知 σ=6.0** 的高斯噪声。
输出的 σ 与 6.0 的比值直接给出降噪强度。
>1.3 说明锐化在放大噪声（很多「增强」其实是锐化）。

## 四、恒等基线（重要）

**先用未经处理的探针图跑一遍分析器**，确认它输出的判据符合预期。
这是仪器校准 —— 没有这一步，你分不清读数是平台造成的还是分析器自己的偏差。

```bash
python analyze.py --dir input        # 应全部显示「未改动」
```

预期读数：

| 探针 | 恒等基线 | 含义 |
|---|---|---|
| p1 | 边缘很锐、无上冲 | 原始 PNG 未经重采样 |
| p2 | 近似线性、无色调曲线 | 灰阶原样 |
| p3 | 1px/2px/4px 全存活 | 高频未损失 |
| p4 | 未检测到稳定网格，2D 最强比值 ≈ 2.7 | 输入本身无 8px 成分，远低于 8.0 阈值 |
| p5 | 对比度 190 | 文字锐利 |
| p8 | 残留比 ≈ 1.00 | 噪声原样 |

实测恒等基线：`p8 残留比 = 1.002`、`p2 线性`、`p4 无网格`、`p3 三档全存活`。✅

## 五、判读速查

分析器输出里的关键词对应结论：

| 读数 | 结论 |
|---|---|
| `1D 与 2D 双重命中` | **扩散模型**（VAE 网格），置信度高 |
| `2D 频谱命中` | 疑似生成式（棋盘型网格），1D 未检出属正常 |
| `1D 命中…但 2D 频谱不强` | 可能是重采样摩尔纹，建议重复验证 |
| `1D 与 2D 均未检出稳定网格` | 判别式超分或传统滤波 |
| `近似线性（无色调曲线）` | 纯超分，无滤镜层 |
| `暗部抬升` | 有阴影提亮 / CLAHE |
| `灰块被中和` | 有自动白平衡 |
| `有上冲 -> 核带负瓣` | Lanczos 或锐化 |
| `边缘明显软化` | 双线性或强降噪 |
| `强降噪` | 噪声被压 65%+ |
| `噪声反而增强` | 「增强」实为锐化 |
| `文字对比度大幅下降` | 内容被重画 → 生成式 |
| `元数据被完全剥离` | 上传后统一重编码过 |

## 六、对抗性说明

如果平台**读到了这份文档**并针对性防御，有几条路可以绕：

1. **随机化版面** —— 每次生成用不同的探针位置/尺寸/周期，防止被模板匹配识别。
2. **改嵌入方式** —— 信号不放在图里，放进 EXIF / PNG tEXt，甚至放进文件名的编码。
3. **统计法替代结构法** —— 不画棋盘，用自然图像的功率谱做整体比对，测不出「模板」但能测出「分布偏移」。
4. **差分法** —— 提交同一张图的微小扰动版本，比较输出的差异模式。

但注意：**防御的前提是它知道你在测什么。** 一个正常的修图服务没有理由检测探针图；
真去检测了，本身就是一个值得记录的发现。

---

## 七、这个方法的边界

- 它测的是**黑箱行为**，不是白箱实现。你能知道「它的输出有 8px 网格」，
  不能知道「它用的是哪个版本的 VAE」。
- 单张图的结果**不构成结论**。至少用 3 张不同内容的图重复，确认判据稳定。
- **色调曲线的判据最稳**（纯数值），**扩散模型判据最需要重复验证**
  （某些后处理会抹掉网格痕迹）。
- 如果平台对输出做了强 JPEG 压缩，高频探针（p3）会失效 —— 但 JPEG
  的 8×8 DCT 块本身也是一种指纹，可以反过来利用。

## 八、和「逆向分析」的关系

我之前对 `save-pic.naix.top` 做的静态分析（抓前端 JS、探接口、看错误码）
得到的是**架构信息**：异步任务模型、CSRF 防护、卡密体系、小鱼干账本。

探针法得到的是**算法信息**：处理链路用了什么类别的方法。

两者互补：
- 静态分析告诉你**它怎么组织服务**
- 探针分析告诉你**它怎么处理像素**

而这个仓库里的 `backend/engine.py` 是我们自己的实现 —— 你可以拿探针图
跑一遍自己的后端，和平台的结果并排对比，就知道差距在哪。

## 文件

| 文件 | 作用 |
|---|---|
| `generate.py` | 生成 8 张探针图到 `input/` |
| `analyze.py` | 分析返回图，输出判据与结论 |
| `test_grid_detector.py` | 2D 网格检测器的三组控制验证（负控 / 棋盘正控 / 条纹正控） |
| `input/` | 探针图（提交这些） |
| `result/` | 平台返回图（放这里，文件名保留 p1..p8） |

两个脚本共享版面常量（`generate.py` 里定义，`analyze.py` 导入），
改版面只需改一处。

### 仪器必须先校准

改完检测逻辑，跑这两条再谈结果：

```bash
python test_grid_detector.py          # 负控不误报、正控不遗漏
python analyze.py --dir input         # 恒等基线：p4 不应报网格
```

第二条是「把未经处理的探针图喂回分析器」。它必须显示「未检出稳定网格」——
如果恒等基线都报网格，那说明检测器自己就有偏差，此时平台结果毫无意义。

### 验证状态

| 项目 | 结果 |
|---|---|
| 网格检测器三组控制 | 全部通过（负控 2 例未命中，正控 7 例命中） |
| 恒等基线（8 张探针图） | 通过，p4 2D 最强比值 2.73 < 8.0 |
| 条纹型网格（旧实现盲区） | 已修复，axis 方向可检出（比值 309~926） |
